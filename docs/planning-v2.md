# SMERP v2 기획서

> 마지막 업데이트: 2026-02-23

## 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 이름 | SMERP v2 (슮엎) |
| 목적 | 사내 ERP — 견적서/품의서/발주서 관리 |
| 스택 | Next.js (App Router) + PostgreSQL + Prisma 7 + AWS S3 |
| 팀 | 진강(기획+개발), 클레버(코딩), 클로버(기획) |

---

## 문서 흐름 (전체)

```
견적서(Quote) → 품의서(Approval) → 발주서(Order)
                    ↓
              계산서(Invoice)
```

- 견적서: 고객에게 보내는 가격 제안
- 품의서: 사내 결재 문서 (매출+매입 포함)
- 발주서: 승인된 품의서 기반 매입처 발주
- 계산서: 매출/매입 세금계산서 추적

## 1. 견적서 (SalesQuote)

### 상태
```
DRAFT → SENT → ACCEPTED / REJECTED
```

### 구조
- **SalesQuote** (견적서 본체)
  - **SalesQuoteProduct** (제품 단위 — "영상편집용 조립PC")
    - **SalesQuoteItem** (개별 부품 — CPU, RAM, SSD...)

### 버전 관리
- `version`, `originalId`, `isLatest`
- 수정 시 새 버전 생성

### 핵심 필드
- 매출처 정보 (회사, 담당자, 연락처)
- 금액 (공급가, VAT, 합계)
- 조건 (납기, 유효기간, 결제조건)

### 구현 상태: ✅ 완료

## 2. 품의서 (SalesApproval)

### 상태 흐름
```
DRAFT → PENDING_TEAM_LEAD → PENDING_CEO → APPROVED
             ↘                    ↘
           REJECTED             REJECTED
```
- PENDING (레거시 호환용 — 이전 버전)

### 결재 3단계
1. **영업담당자** (salesManager) — 상신
2. **영업팀장** (teamLeader) — 1차 승인
3. **대표이사** (CEO) — 최종 승인

### 구조
- **SalesApproval** (품의서 본체)
  - **SalesApprovalProduct** (매출 단위 = 매출 계산서 단위)
    - **SalesApprovalItem** (개별 부품 + 매입 정보)

### 견적서 → 품의서 변환
- v1.0에서는 변환 플로우 삭제 예정
- 견적서/품의서 각각 독립 작성
- 추후 필요 시 연결 기능 추가

### 수정/회수 규칙 ✅
| 상태 | 수정 | 동작 |
|------|------|------|
| DRAFT | ✅ 자유 | 제한 없음 |
| PENDING~ | ✅ 자동회수 | → DRAFT + 서명 전체 초기화 |
| APPROVED | ❌ | revise(새 버전) 사용 |
| REJECTED | ❌ | 수정 불가 |

### 버전 관리
- `approvalCode` — 버전 간 공유 (D251202-01)
- `version` — 1, 2, 3...
- `isLatest` — 최신 버전만 true
- revise: 기존 APPROVED(isLatest=false) → 새 DRAFT(isLatest=true)
- `sourceProductId`, `sourceItemId`로 품목 추적

### 가시성
- DRAFT: 작성자만
- PENDING~APPROVED~REJECTED: 전체

### 계산서 자동생성 (APPROVED 시)
- 매출 계산서: Product 단위 (1 product = 1 매출 계산서)
- 매입 계산서: vendorName 기준 그룹핑

### API 목록
| API | 설명 | 상태 |
|-----|------|------|
| GET/POST /sales-approvals | 목록/생성 | ✅ |
| GET/PATCH /sales-approvals/[id] | 상세/수정 | ✅ |
| POST /[id]/submit | 상신 | ✅ |
| POST /[id]/sign | 서명(승인) | ✅ |
| POST /[id]/reject | 반려 | ✅ |
| POST /[id]/withdraw | 회수(→DRAFT) | ✅ |
| POST /[id]/revise | 수정발행(새버전) | ✅ |
| GET /[id]/versions | 버전 목록 | ✅ |
| GET /[id]/compare | 버전 비교 | ✅ |
| GET /[id]/excel | 엑셀 다운로드 | ✅ |
| POST /[id]/files | 파일 첨부 | ✅ |
| POST /upload | 엑셀 업로드 파싱 | ✅ |
| GET /next-code | 다음 품의코드 | ✅ |

### 구현 상태: ✅ API 완료, 프론트 진행중

## 3. 발주서 (SalesOrder)

### 개념
품의서 승인 데이터에서 **매입처별로 뽑아서** 발주서 양식에 채우는 것.
발주서 자체에 새로운 데이터는 거의 없음 — 품의서의 매입 뷰.

### 생성 방식
```
품의서 APPROVED
  └─ Item들을 vendorName별 그룹핑
       └─ vendorName A → 발주서 1장
       └─ vendorName B → 발주서 1장
```

### 발주서 양식 (엑셀 기준)
**헤더:**
- 수신: 매입처 (DELL KOREA 등)
- 발주자: 우리 회사 (서버메이트)
- 발주일자
- 납품/작업장소
- 담당자 (이름, 연락처)
- 결제조건 (예: 계산서 발행 후 90일 현금)
- 발주담당

**품목 테이블:**
- 제품명 (행 1) + 총 금액
- 개별 부품 (Part No. / 품목 / 수량 / 소비자가 / 공급단가 / 금액)
- 합계 / VAT / 총합계

**비고**

### 발주 고유 필드
- 발주일자
- 납품장소 (품의서의 deliveryAddress에서 복사 가능)
- 결제조건 (품의서의 paymentTerms에서 복사 가능)
- 발주담당

### 상태
```
DRAFT → ORDERED → DELIVERED
                → CANCELLED
```

### PDF 출력
- 발주서는 PDF로 변환해서 매입처에 전달
- 엑셀 템플릿 → PDF 변환 필요

### 구현 상태: 🔲 스키마만 존재, 매입처별 분리 로직 미구현

## 5. MA (유지보수) 문서

### Sales와의 차이
| | Sales | MA |
|---|-------|-----|
| 대상 | 장비/부품 납품 | 유지보수 계약 |
| 구조 | Product → Item (2단계) | **플랫 (1행 = 1계약)** |
| 금액 | 일회성 | **월 단위 × 계약기간** |
| 핵심 필드 | P/N, 품목스펙, 매입처별 | SM코드, 벤더코드, 모델/M-T/S/N, 계약기간, 청구구분, GP율 |
| 매입 | 품목별 다수 매입처 | **계약별 1:1 매입처** |

### MA 견적서
- 발신: 매입처(서버메이트 등) → 수신: 고객사
- 장비별 유지보수 서비스 제안
- 필드: 모델, M/T, S/N, 기기명&상세SPEC, 수량, 서비스개시일, 서비스종료일, 월제안가, 계약기간 총계
- SLA 정보: 24×7×365, 4Hr Response 등

### MA 품의서
- 1행 = 1계약
- 매출: 고객사, 매출가, 청구구분(월간), 계약기간
- 매입: 매입처(LENOVO 등), 매입가, 청구구분, 계약기간
- GP: 계약기간 총GP, GP율
- 서명란: 대표이사/영업팀장/영업담당/출고 (Sales와 동일)

### MA → 계산서
- 계약 1건 = 매출 계산서 1건 + 매입 계산서 1건
- Sales보다 단순 (1:1 관계)

### 구현 상태: 🔧 기본 CRUD 있음, MA 전용 필드 미반영

## 6. 경영팀 (Management)

### 6-1. 계산서 발행현황
→ `docs/invoice-status-spec.md` 참고

### 6-2. 매출 대장 (월별 상세)

월별 탭으로 관리. 모든 매출/매입 건의 원본 데이터.

**컬럼:**
| 컬럼 | 설명 | 데이터 출처 |
|------|------|-----------|
| 품의코드 | D251231-01 등 | approval.approvalCode |
| Vendor 코드 | | 벤더코드 (MA) |
| 날짜 | 거래일 | approval.approvalDate |
| 매출처 | 고객사 | approval.clientCompany |
| END-USER | 최종 사용자 | approval.endUser |
| 구분 | 상품/MA/건설임대 등 | 카테고리 |
| MA:청구구분 | 월간-IBM, 월간-레노버 등 | MA 전용 |
| 거래내용 | 상세 설명 | product.name / 거래 설명 |
| 공급가액 | 매출 금액 | product.totalPrice |
| 부가세 | VAT | 자동계산 (10%) |
| 매입액 | 매입 합계 | SUM(item.purchaseTotal) |
| 매입거래처 | 매입처별 상세 | item.vendorName + 금액 |
| GP | 매출 - 매입 | 자동계산 |
| 입금일 | 대금 수금일 | **수동 입력 (경영팀)** |
| 영업 상태 | 완료/미완 | **수동 입력** |
| 담당자 | 영업 담당 | approval.managerName |

### 6-3. 매출 요약 (분류 탭)

**월별 매출 요약:**
- 월 / 공급가액 / 부가세 / 합계 / 건수 / GP

**개인별 매출:**
- 담당자별 매출 합산 (MA/상품 구분)

**업체별 매출 랭킹:**
- Rank / 업체명 / 총매출
- 카테고리별 분류: 상품, MA, MAPAC, WSU, 장비임대, 건설임대
- GP / 수익율

### 카테고리 분류 체계
| 카테고리 | 설명 |
|---------|------|
| 상품 | 장비/부품 납품 (Sales 품의서) |
| MA | 유지보수 계약 |
| MAPAC | ❓ 확인 필요 |
| WSU | ❓ 확인 필요 |
| 장비임대 | 장비 임대 |
| 건설임대 | 건설 장비 임대 |

> ⚠️ MAPAC, WSU 분류 기준 — 진강 확인 필요

### 6-4. 매입 대장

매출 대장과 동일 구조, 매입 관점.

**분류 탭:** 월별 매입 합산 + 업체별 매입 랭킹 (상품/MA/MAPAC/WSU/장비임대/일반경비 등)

**월별 탭:**
| 컬럼 | 설명 |
|------|------|
| 품의코드 | |
| Vendor 코드 | |
| 계산서일 | 매입 계산서 발행일 |
| 매입처 | |
| 매출처 | 최종 고객사 |
| 구분 | MA/상품 |
| MA:청구구분 | 월간-IBM 등 |
| 상품:P/N | |
| 품목 | 거래 내용 |
| 공급가액 / VAT / 합계금액 | |
| 완료 (트루스캐줄) | 매입 대금 지급 완료 여부 |
| 영업 | 담당자 |
| 매출처 | |
| 비고 | 세금유형(비과세/영세) 등 |

**Master 탭:** 월별 데이터 전체 합산 (연간 뷰). 월별 탭에서 SUMIF로 참조.

### 매출/매입 대장 = 같은 데이터의 양면
- 품의서 승인 데이터에서 매출 관점 = 매출 대장
- 품의서 승인 데이터에서 매입 관점 = 매입 대장
- 별도 입력 없이 품의서 + 계산서 발행현황에서 자동 집계 가능

### 6-5. 외상매출 입금예정 / 외상매입 출금예정

매출/매입 대장의 뷰 변형:
- **월별 탭**: 날짜순
- **업체별 탭**: 거래처별 그룹핑 + 소계
- **추가 필드**: 입금예정일 (매출) / 지급예정일 (매입)

→ 별도 테이블 불필요. 매출/매입 대장에 입금예정일/지급예정일 필드 추가 + 뷰 필터로 해결.

### 6-6. 매출 랭크 (비밀보호)

업체별 매출/GP/수익율 랭킹. 분류 탭의 업체별 매출 랭킹과 동일 구조.
- 민감 데이터 (GP, 수익율) → 권한 제어 필요 (FINANCE/ADMIN만 접근)

### 경영팀 화면 요약

| 화면 | 데이터 출처 | 핵심 |
|------|-----------|------|
| 계산서 발행현황 | 품의서 승인 → 자동생성 | 매출/매입 계산서 상태 추적 |
| 매출 대장 | 계산서 + 품의서 | 월별/연간 매출 원장 |
| 매입 대장 | 계산서 + 품의서 | 월별/연간 매입 원장 |
| 외상매출 입금예정 | 매출 대장 + 입금예정일 | 수금 스케줄 |
| 외상매입 출금예정 | 매입 대장 + 지급예정일 | 지급 스케줄 |
| 매출 요약/랭킹 | 매출 대장 집계 | 담당자별/업체별/카테고리별 |

> **핵심: 모든 데이터의 원천은 품의서 승인.** 경영팀 화면은 전부 품의서 데이터의 집계/뷰.
