# 문서 편집 가이드

이 디렉토리는 `/project-spec:update` 실행 시 일부가 자동 갱신됩니다. 수동 편집이 살아남는 곳과 덮어써지는 곳을 구분하세요.

## 자동 재생성 (수동 편집 보존 안 됨)

- `README.md` — 매 update마다 전체 재생성
- `_meta.yml` — 매 update마다 갱신
- 영향받은 기능 파일의 본문 — git diff에 걸린 파일이 속한 기능은 재생성

## 사용자 편집 가능 (보존됨)

- **`DOMAINS.md`** — 도메인 분류 규칙. 섹션 추가/제거/rename 후 `/update` 실행 시 기능들이 재배치됩니다.
- `_결정대기.md`의 각 항목 — 항목 아래 `**결정**: <선택지>` 라인을 추가하면 다음 update에서 감지해 해당 기능 파일에 반영 시도 후 결정 항목을 제거합니다.
- 영향받지 **않은** 기능 파일 — update가 건드리지 않습니다.
- 도메인 폴더 구조 — 파일을 다른 폴더로 수동 이동한 경우 frontmatter의 `domain` 필드도 함께 수정 필요.

## 도메인 변경 워크플로

1. `DOMAINS.md` 편집 (추가/제거/rename)
2. `/project-spec:update` 실행
3. 재배치 확인 대화 → yes
4. 기능 파일들이 새 도메인 폴더로 자동 이동

## frontmatter `_files`

이 glob이 "어떤 코드 변경이 어떤 기능에 영향을 주는지"를 결정합니다. 수정 시 glob 형식을 유지해야 update가 올바르게 동작합니다.

## 수동 메모 남기기

기능 파일 본문은 update로 덮어써질 수 있어 수동 메모에는 부적절합니다. 대신:

- 간단한 사실 보정은 기능 파일 본문을 수정한 뒤, 코드 변경이 발생하기 전까지만 보존됩니다.
- 영구 메모는 `_결정대기.md`의 해당 항목에 누적하거나, `docs/features/NOTES.md` 같은 별도 파일을 만드세요. update는 이 파일을 건드리지 않습니다.
