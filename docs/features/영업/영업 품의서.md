# 영업 품의서 🟢

영업 건의 사내 결재를 진행한다. 3단계 서명(영업담당 → 팀장 → CEO), 반려/철회/회수, 승인 시 매출장/매입장(원장)·계산서 발행 기록(InvoiceRecord) 자동 생성, revise 체인 버전 관리, 카테고리·세금유형 기반 VAT 자동 계산을 포함한다. 2026-04-22 PR #11로 **결재선 명시 지정(상신 시점 모달)** 플로우가 적용되어 `BUSINESS_RULES.md` §5 (결정대기 #3 — C안) 전면 구현이 완료되었다.

**진행률** ███████████████████░ 98%

## 사용자 플로우

1. 견적서 기반으로 품의서 생성하거나 신규 작성
2. 제품별로 카테고리(상품 / MA) 선택 (`BUSINESS_RULES.md` §1 — 세금은 VAT 10% 고정, 매출 계산서는 제품 단위 고정이라 별도 선택 UI 없음)
3. 품목별 매입 정보, 매출/매입 계산서 필요 여부(`salesInvoiceRequired` / `purchaseInvoiceRequired`) 입력
4. **상신 버튼 클릭 → `<ApprovalLineModal>`에서 결재자 3명 지정** (영업담당/팀장/CEO 드롭다운, 기본값 자동 채움) → 확정 시 DRAFT → PENDING_TEAM_LEAD
5. 팀장 서명(PENDING_CEO) → CEO 서명(APPROVED) — `sign API`는 TEAM_LEADER/CEO 단계만 처리 (영업담당 서명은 상신 단계에서 이미 기록됨)
6. 승인 시 자동 생성:
   - 매출장/매입장 원장 (카테고리 반영, VAT 10% 고정)
   - 매출 InvoiceRecord (제품당 1건 — 식별 키 `(approvalId, productId)`, `source=SALES_APPROVAL`)
   - 매입 InvoiceRecord (매입처별 자동 그룹핑 — 식별 키 `(approvalId, vendorCompany)`, `source=SALES_APPROVAL`)
7. 수정 필요 시 revise로 새 버전 생성 — 이전 원장은 `isActive=false`·`cancelReason=REVISED_v{n}`으로 비활성화, ISSUED 상태인 계산서는 `NEEDS_AMENDMENT`로 전이

**Entry points**
- `app/api/sales-approvals/[id]/submit/route.ts` — 기안/상신 API. body로 `salesManagerId`/`teamLeaderId`/`ceoId` 수신, 상신 시 영업담당 서명(`salesManagerSignedAt`)도 함께 기록하고 `PENDING_TEAM_LEAD`로 전이 (BUSINESS_RULES §5)
- `app/api/sales-approvals/[id]/sign/route.ts` — **TEAM_LEADER / CEO 단계만** 처리 (SALES_MANAGER 제거). CEO 승인 시 원장·InvoiceRecord 자동 생성, revise-aware 이전 원장 비활성화 + ISSUED→NEEDS_AMENDMENT 전이, `calculateVat`(10% 고정)
- `app/api/sales-approvals/[id]/revise/route.ts` — 새 버전 생성 + 제품/품목 복제 (sourceProductId·sourceItemId 연결)
- `app/api/sales-approvals/route.ts` — 목록/생성 (category enum 적용, invoiceRequired 기본값 true)
- `app/api/sales-approvals/[id]/route.ts` — 상세/수정/삭제 (DRAFT만 삭제 가능, PENDING 계열 수정 시 DRAFT 자동 회수)
- `app/api/sales-approvals/[id]/reject/route.ts` — 반려
- `app/api/sales-approvals/[id]/withdraw/route.ts` — 회수 (PENDING 계열 → DRAFT, PENDING 상태 InvoiceRecord 삭제)
- `app/api/sales-approvals/[id]/compare/route.ts` — 버전 간 diff
- `components/documents/ApprovalLineModal.tsx` — 영업/MA 품의서가 공유하는 결재선 지정 모달

**주요 라이브러리**: exceljs, @aws-sdk/client-s3

**의존성 서비스**: PostgreSQL (Prisma — SalesApproval / SalesApprovalProduct / SalesApprovalItem / SalesApprovalFile / InvoiceRecord / SalesLedger / PurchaseLedger), AWS S3, 알림 시스템 (`lib/notifications/sender.ts`)

**핵심 난제 (메모)**: 품의서↔원장↔InvoiceRecord 3중 연동의 revise 체인. `sign/route.ts`는 `rootApprovalId`를 체인 루트로 고정하고 `approvalVersion`·`isActive`·`cancelledAt`·`cancelReason`으로 이전 버전 원장을 논리 삭제한다. 원장 집계 시 `isActive: true` 필터 필수. InvoiceRecord는 별개 체인(`amendedFromId`)으로 관리되며 revise와는 독립 작동. `source` 필드(SALES_APPROVAL / MA_BILLING)로 계산서의 원천을 구분한다.
