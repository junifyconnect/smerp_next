# 영업 품의서 🟢

영업 건의 사내 결재를 진행한다. 3단계 서명(영업담당 → 팀장 → CEO), 반려/철회/회수, 승인 시 매출장/매입장(원장)·계산서 발행 기록(InvoiceRecord) 자동 생성, revise 체인 버전 관리, 카테고리·세금유형 기반 VAT 자동 계산을 포함한다.

**진행률** ███████████████████░ 95%

## 사용자 플로우

1. 견적서 기반으로 품의서 생성하거나 신규 작성
2. 제품별로 카테고리(상품 / MA) 선택 (`BUSINESS_RULES.md` §1 — 세금은 VAT 10% 고정, 매출 계산서는 제품 단위 고정이라 별도 선택 UI 없음)
3. 품목별 매입 정보, 매출/매입 계산서 필요 여부(`salesInvoiceRequired` / `purchaseInvoiceRequired`) 입력
4. 결재 상신 (DRAFT → PENDING_TEAM_LEAD)
5. 팀장 서명(PENDING_CEO) → CEO 서명(APPROVED)
6. 승인 시 자동 생성:
   - 매출장/매입장 원장 (카테고리 반영, VAT 10% 고정)
   - 매출 InvoiceRecord (제품당 1건 — 식별 키 `(approvalId, productId)`)
   - 매입 InvoiceRecord (매입처별 자동 그룹핑 — 식별 키 `(approvalId, vendorCompany)`)
7. 수정 필요 시 revise로 새 버전 생성 — 이전 원장은 `isActive=false`·`cancelReason=REVISED_v{n}`으로 비활성화, ISSUED 상태인 계산서는 `NEEDS_AMENDMENT`로 전이

<summary>🔧 기술 정보 (개발자용)</summary>

**Entry points**
- `app/api/sales-approvals/[id]/sign/route.ts` — 3단계 결재 서명 + 승인 시 원장·InvoiceRecord 자동 생성, revise-aware 이전 원장 비활성화 + ISSUED→NEEDS_AMENDMENT 전이, `calculateVat`(10% 고정)
- `app/api/sales-approvals/[id]/revise/route.ts` — 새 버전 생성 + 제품/품목 복제 (sourceProductId·sourceItemId 연결)
- `app/api/sales-approvals/route.ts` — 목록/생성 (category enum 적용, invoiceRequired 기본값 true)
- `app/api/sales-approvals/[id]/route.ts` — 상세/수정/삭제 (DRAFT만 삭제 가능, PENDING 계열 수정 시 DRAFT 자동 회수)
- `app/api/sales-approvals/[id]/submit/route.ts` — 결재 상신
- `app/api/sales-approvals/[id]/reject/route.ts` — 반려
- `app/api/sales-approvals/[id]/withdraw/route.ts` — 회수 (PENDING 계열 → DRAFT, PENDING 상태 InvoiceRecord 삭제)
- `app/api/sales-approvals/[id]/compare/route.ts` — 버전 간 diff

**주요 라이브러리**: exceljs, @aws-sdk/client-s3

**의존성 서비스**: PostgreSQL (Prisma — SalesApproval / SalesApprovalProduct / SalesApprovalItem / SalesApprovalFile / InvoiceRecord / SalesLedger / PurchaseLedger), AWS S3, 알림 시스템 (`lib/notifications/sender.ts`)

**핵심 난제 (메모)**: 품의서↔원장↔InvoiceRecord 3중 연동의 revise 체인. `sign/route.ts`는 `rootApprovalId`를 체인 루트로 고정하고 `approvalVersion`·`isActive`·`cancelledAt`·`cancelReason`으로 이전 버전 원장을 논리 삭제한다. 원장 집계 시 `isActive: true` 필터 필수. InvoiceRecord는 별개 체인(`amendedFromId`)으로 관리되며 revise와는 독립 작동.
