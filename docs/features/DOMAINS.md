# smerp_next 도메인 정의

이 파일은 프로젝트의 도메인 분류 규칙을 고정합니다. `/project-spec:update` 실행 시 에이전트가 먼저 읽어 분류 기준으로 사용합니다.

---

## 도메인 목록

## 영업
영업팀이 담당하는 프로세스. 영업 품의서, 견적서, 발주서, 수주 관리.

## MA
유지보수(Maintenance Agreement) 계약 관련. MA 견적서, MA 품의서. 영업과 별개의 프로세스·결재 라인을 가짐.

## 경영관리
회계 영역. 경영팀이 관리. 계산서 발행, 매출장, 매입장, 경영 통계.

## 관리자
운영 마스터 관리. 직원 관리, 휴가 관리, 매출처/매입처 마스터, 엑셀 일괄 업로드, 엑셀 양식 관리.

## 공통
전체 유저가 일상적으로 사용하는 기능. 마이페이지, 캘린더, 대시보드 등 유저가 직접 화면에서 쓰는 공통 기능.

## 시스템
백엔드 횡단 서비스. 인증, 알림, S3 클라우드 스토리지 등 다른 기능이 기반으로 쓰는 인프라성 서비스.

---

## 분류 힌트

```yaml
path_prefix:
  "app/sales/**": 영업
  "app/api/sales/**": 영업
  "app/ma/**": MA
  "app/api/ma/**": MA
  "app/management/**": 경영관리
  "app/api/management/**": 경영관리
  "app/admin/**": 관리자
  "app/api/admin/**": 관리자
  "app/(auth)/**": 시스템
  "app/api/auth/**": 시스템
  "lib/auth/**": 시스템
  "lib/notification/**": 시스템
  "lib/s3/**": 시스템

keywords:
  품의서: 영업
  견적서: 영업
  발주서: 영업
  수주: 영업
  MA: MA
  유지보수: MA
  계산서: 경영관리
  매출장: 경영관리
  매입장: 경영관리
  경영: 경영관리
  직원: 관리자
  휴가: 관리자
  매출처: 관리자
  매입처: 관리자
  엑셀: 관리자
  인증: 시스템
  로그인: 시스템
  알림: 시스템
  S3: 시스템
  스토리지: 시스템
  마이페이지: 공통
  캘린더: 공통
  대시보드: 공통
```

**참고**: path_prefix는 `"MA"`나 `"영업"` 같은 한국어 키워드가 실제 디렉토리명에 없을 가능성이 높음. 실제 프로젝트 구조 확인 후 조정 필요. 위 힌트는 가정이며, 실제 경로에 맞게 편집하세요.

---

## 편집 규칙

- **도메인 추가**: `## <도메인명>` 섹션 추가 + 설명
- **도메인 제거**: 섹션 삭제. 다음 update에서 소속 기능이 재배치됨
- **rename**: 섹션 제목 변경. update가 폴더도 rename
- **분류 힌트**: 자주 틀리는 케이스에만 추가. 너무 상세하면 오히려 혼란
