# 매출처 관리 🟢

거래하는 고객사(매출처)를 등록하고 관리한다. 회사별 다중 담당자 관리를 지원하고, 견적서/품의서 작성 시 고객사 선택 모달에서 참조된다.

**진행률** ████████████████████ 100%

## 사용자 플로우

1. 매출처 목록에서 회사명 검색
2. 신규 매출처 등록 (회사명, 전화, 팩스, 주소, 비고)
3. 상세 페이지에서 담당자 추가/수정 (이름/부서/직급/전화/휴대폰/이메일)
4. 기본 담당자 지정 (`isDefault`)

## 완료

- ✅ 매출처 CRUD
- ✅ 회사명 검색
- ✅ 담당자 다중 관리 (CustomerContact)
- ✅ 기본 담당자 지정
- ✅ 상세 페이지
- ✅ 신규 등록 모달
- ✅ 거래처 모델 필드명 통일 (Customer/Vendor 모두 `name` 사용)

## 남은 것

없음.

## 관련 화면

- `/admin/customers` (매출처 목록)
- `/admin/customers/[id]` (매출처 상세)

<summary>🔧 기술 정보 (개발자용)</summary>

**Entry points**
- `app/(main)/admin/customers/page.tsx` — 매출처 목록 (Server Component)
- `app/(main)/admin/customers/[id]/page.tsx` — 매출처 상세
- `app/api/customers/route.ts` — CRUD API (`orderBy: { name: 'asc' }`, `where: { name: { contains } }`)
- `app/api/customers/[id]/contacts/route.ts` — 담당자 CRUD
- `app/api/customers/[id]/contacts/[contactId]/route.ts` — 담당자 개별 수정/삭제

**DB 스키마 (Prisma — Customer)**
- 필드명: `name` (이전 `companyName` → 리네임)
- DB 컬럼명: `name` (이전 `company_name` → RENAME 마이그레이션 적용, `@map` 제거)
- 인덱스/unique constraint도 재생성됨
- Vendor는 이미 `name`이었기 때문에 이 변경으로 거래처 모델 필드가 일관됨

**필드 호환 메모**
- `SelectedCustomerData` 콜백의 `companyName` 키는 문서 폼 내부 계약이라 유지
- `notifyPaymentDue` 파라미터의 `companyName`은 Customer/Vendor 중립 표현이라 유지

**주요 라이브러리**: 없음

**의존성 서비스**: PostgreSQL (Prisma — Customer, CustomerContact)
