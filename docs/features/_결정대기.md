## 1. 🔥 MA 품의서 승인 시 원장/InvoiceRecord 생성 여부

**상태**: ✅ **결정 확정 + 구현 완료** (2026-04-22 PR #9~#15)

**문제**:
- 영업 품의서는 APPROVED 시 매출장·매입장 + 매출/매입 InvoiceRecord 자동 생성 (`BUSINESS_RULES.md` §5)
- MA 품의서는 APPROVED 시 `MAContract` + `MABilling` N건만 생성 → **원장/InvoiceRecord 미생성**
- 결과: MA 매출이 `경영 통계`, `계산서 발행 현황`에서 **영구 누락**. 회계 보고 정합성 깨짐
- 위치: `docs/features/MA/MA 품의서.md:26,41-43` vs `docs/features/영업/영업 품의서.md:28-32`

**선택지**:
- **A**: MA 승인 시에도 원장 + InvoiceRecord 자동 생성 (영업과 동일 처리 + `MAContract` 별도 보존)
- **B**: `MABilling`을 원장 대체 엔티티로 공식화 — 경영 통계/계산서 발행 현황에서 `MABilling`도 함께 집계하도록 API 개정
- **C**: MA는 별도 회계 라인으로 두고, 통합 집계는 하지 않음 (실무상 허용되는지 확인 필요)

**영향 범위**: MA 품의서, 경영 통계, 계산서 발행 현황, 매출장 매입장 (4개 기능)

**결정**: **B (MABilling을 원장 대체 엔티티로 격상) + B-2 (InvoiceRecord 파생)**

### 세부 설계 (2026-04-22 확정)

**1. 원장 이중 구조**
- 영업: `SalesLedger` / `PurchaseLedger`
- MA: `MABilling` (월별 청구 스케줄 = 원장 역할)
- 집계 API(경영 통계, 계산서 발행 현황)는 양쪽을 UNION 처리

**2. 계산서는 InvoiceRecord로 통합 (B-2)**
- 영업: 품의서 APPROVED 시 InvoiceRecord 즉시 생성
- MA: MABilling에서 `/api/management/invoices/issue` 호출 시 InvoiceRecord **파생 생성**
- 매출/매입 발행 현황 페이지는 그대로 InvoiceRecord만 보면 됨

**3. MA revise는 영업과 동일 패턴**
- v1 MABilling 전체 → `isActive=false` 비활성화
- ISSUED 상태 InvoiceRecord → `NEEDS_AMENDMENT` 전이 (물리 삭제 X, 수정세금계산서 발행 유도)
- PENDING 상태 InvoiceRecord → `CANCELLED('REVISED_vN')` 로 버림
- v2 MAContract + MABilling 신규 생성

**4. 계약 기간 유연 처리**
- `MAApprovalItem.startDate` / `endDate` 필수 유지
- MABilling은 **월 단위 1건씩** 생성 (시작 월 ~ 종료 월)
- **일할 계산 없음** — 시작 월/종료 월 모두 통째로 1개월치 청구
- 청구 기준일: `MAApprovalItem.billingDayOfMonth` (계약마다 다름) 추가
  - 기본값: 말일 (31 또는 해당 월의 말일)
- MABilling 각 행: `billingMonth` (월 식별자), `dueDate` (실제 청구 기준일)

### 후속 구현 작업 (PR 단위)

1. **스키마 개정**:
   - `MAApprovalItem.billingDayOfMonth Int? @default(31)` 추가
   - `MAContract`, `MABilling` 모델 확정 (아직 미구현)

3. **InvoiceRecord 파생 로직**:
   - `/api/management/invoices/issue` 에서 MABilling 소스도 처리

4. **집계 API 개정**:
   - `경영 통계`: SalesLedger + MABilling UNION
   - `계산서 발행 현황`: InvoiceRecord 기반이라 자동 반영

5. **BUSINESS_RULES.md §1/§5/§7 갱신**: MA 규칙 추가

## 3. 결재선 자동 매칭 규칙 (복수 팀장/CEO)

**상태**: ✅ **결정 확정 + 구현 완료** (2026-04-22 PR #11)

**문제**:
- `BUSINESS_RULES.md` §5가 "SALES_MANAGER → TEAM_LEADER → CEO 역할 기반 자동 매칭"이라 정의
- 그러나 SALES 팀에 팀장이 2명 이상일 때 누구를 서명자로 고르는지 규칙이 없음
- `영업 품의서.md:59`에 "결재선 지정 UI (남은 것)"로 기록되어 있지만 필수/nice-to-have 구분 없음

**선택지 (매칭 규칙)**:
- **A**: 작성자 소속 부서(SALES 등)의 가장 최근 등록된 팀장 1명
- **B**: 작성자 소속 부서의 **모든** 팀장에게 병렬 알림, 먼저 서명한 사람이 진행
- **C**: 작성자가 품의서 생성 시 **직접 결재자 선택** (결재선 지정 UI 구현 필수)

**선택지 (결재선 UI 우선순위)**:
- **필수**: C안과 연결, MVP에 포함
- **Nice-to-have**: A/B로 자동 매칭 + 나중에 UI 추가

**결정 (매칭 규칙)**: **C (명시적 지정)**

**결정 (UI 우선순위)**: **필수 (MVP 포함)**

### 세부 설계 (2026-04-22 확정)

**실무 전제**: 현재 팀장 1명 + CEO 1명. 그러나 **부재/휴가/퇴사** 가능성을 고려해 자동 매칭은 위험(매칭 대상자 없으면 상신 자체 불가).

**1. 지정 타이밍: C-2 (상신 시점)**
- 품의서 **작성 폼엔 결재자 필드 없음** (작성은 단순하게)
- **상신 버튼 클릭 시 모달**에서 결재선 선택 후 확정
- 이유: 작성~상신 사이 며칠 걸리면 원래 결재자가 부재 중일 수 있음. 상신 직전에 고르는 게 유연
- 기본값은 자동 채움 (`role=TEAM_LEADER` / `role=CEO`의 첫 번째 사용자) → 대부분 확인만 하고 상신 → 실무 피로도 낮음

**2. 대리자 선택 범위: 옵션 다 (아무나 선택 가능)**
- 역할(role) 체크 없이 활성 사용자 전체에서 드롭다운 선택
- 이유: 소규모 조직이라 권한 위계 체크 불필요. 사용자 판단 신뢰
- 향후 팀 커지면 role 필터 추가 가능

**3. 스키마**
- 영업: `SalesApproval.salesManagerId` / `teamLeaderId` / `ceoId` (이미 존재, 이제 **상신 시 세팅**)
- MA: `MAApproval`에 동일 3개 필드 추가 필요 (#1 스키마 작업과 합칠 수 있음)
- 모두 nullable — DRAFT 상태에선 null, 상신 시 세팅, 승인 시 `*SignedAt` 기록

**4. UI (상신 모달)**
```
┌─ 결재선 지정 ─────────────────────┐
│ 영업담당  [ 김사원 ▼ ]  (기본: 작성자)
│ 팀장      [ 박팀장 ▼ ]  (기본: role=TEAM_LEADER 첫 번째)
│ CEO       [ 홍사장 ▼ ]  (기본: role=CEO 첫 번째)
│         [ 취소 ]  [ 상신 ]
└───────────────────────────────────┘
```
- 각 드롭다운: `isActive=true`인 활성 사용자 전체 목록
- 기본값 자동 채움 → 수정 가능

### 후속 구현 작업

1. **스키마**: `MAApproval` 결재 필드 3개 추가 (#1 MA 스키마 작업과 합침)
2. **상신 API**: 기존 `submit/route.ts`를 body에서 `salesManagerId`/`teamLeaderId`/`ceoId` 받도록 개정
3. **UI**: `<ApprovalLineModal>` 컴포넌트 신설 → 영업/MA 품의서 상세 화면의 상신 버튼에서 사용
4. **사용자 목록 API**: `GET /api/users?isActive=true` 기존 API 재사용
5. **영업 기존 자동 매칭 로직 제거**: 현재 `sign/route.ts`가 DB에서 role로 조회하는 부분 있으면 제거하고, 품의서에 저장된 `salesManagerId`/`teamLeaderId`/`ceoId` 사용

### ✅ 구현 완료 (2026-04-22, PR #11)

- `components/documents/ApprovalLineModal.tsx` 신설 (영업/MA 품의서 공유). 기본값 자동 채움 + 활성 사용자 전체에서 대리자 선택 가능.
