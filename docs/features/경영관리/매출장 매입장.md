# 매출장 매입장 🟡

품의서 승인 시 자동 생성되는 매출장/매입장(원장)을 조회·관리한다. revise 체인을 지원하는 `isActive` 필터와 출처 추적 필드가 적용되어 있으며, API는 완성되어 있으나 전용 프론트엔드 페이지는 없다. 결제 상태 관리, 연체 관리, 원장 직접 수정, 외상매출금 관리를 위한 전용 페이지 개발이 확정되었다.

**진행률** ██████████████░░░░░░ 70%

## 제공 기능

- 매출장/매입장 목록 조회 (다양한 필터 조합, `isActive=true` 기본)
- 개별 원장 상세 조회 및 수정
- 연체 업체 조회 (매출장 기준)
- 결제 상태/예정일 관리
- revise로 비활성화된 과거 버전 원장 자동 제외

## 완료

- ✅ 매출장 목록 조회 API (카테고리/매출처/담당자/결제상태/기간 필터)
- ✅ 매입장 목록 조회 API (카테고리/매입처/매출처/유형/결제상태/기간 필터)
- ✅ 개별 매출장/매입장 상세/수정 API
- ✅ 페이지네이션 및 집계 (supplyAmount/vatAmount/totalAmount/grossProfit 합산)
- ✅ `isActive` 기반 revise 추적 — 매출장/매입장 목록 GET의 기본 `where`에 `isActive: true` 하드코딩, 연체/통계도 일관 적용
- ✅ `cancelledAt`/`cancelReason` 필드 지원 (revise 시 `REVISED_v{n}` 값 기록)
- ✅ `sourceProductId`/`sourceItemId`/`approvalVersion` 역참조 필드 (원장 → 원본 품의서 행)
- ✅ `salesApprovalId`가 체인 루트 품의서 ID로 고정 (revise 시에도 동일)
- ✅ 매입장 특수 유형 (INVOICE/CASH/CARD/IMPORT)
- ✅ 연체 업체 조회 API (결제예정일 경과 + 미결제 + `isActive: true`)
- ✅ 연체일수 자동 계산 + 업체별 연체 합계 집계

## 남은 것

- ❌ `app/(main)/management/sales-ledger/` 매출장 목록/상세/편집 페이지
- ❌ `app/(main)/management/purchase-ledger/` 매입장 목록/상세/편집 페이지
- ❌ 결제 상태 편집 UI (PENDING/PARTIAL/PAID 전환, 결제일 입력)
- ❌ 연체 필터 UI (기존 `overdue` API 연동, 연체일수 기준 정렬)
- ❌ 외상매출금 대시보드 섹션 (업체별 미수금 합계, 연체 경고)
- ❌ 비활성화된(isActive=false) 원장의 이력 조회 UI (cancelReason 표시)

## API 엔드포인트

- `GET /api/management/sales-ledger` — 매출장 목록 (필터/페이지네이션, isActive=true)
- `GET /api/management/sales-ledger/[id]` — 매출장 상세
- `PATCH /api/management/sales-ledger/[id]` — 매출장 수정 (결제 상태 등)
- `POST /api/management/sales-ledger` — 매출장 수동 등록 (품의서 외 경로용)
- `GET /api/management/sales-ledger/overdue` — 연체 업체 (isActive=true + PENDING/PARTIAL + 예정일 경과)
- `GET /api/management/purchase-ledger` — 매입장 목록 (isActive=true)
- `GET /api/management/purchase-ledger/[id]` — 매입장 상세
- `PATCH /api/management/purchase-ledger/[id]` — 매입장 수정
- `POST /api/management/purchase-ledger` — 매입장 수동 등록
