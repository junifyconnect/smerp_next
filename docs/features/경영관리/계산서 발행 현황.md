# 계산서 발행 현황 🟢

승인된 품의서의 계산서 발행/수정/취소를 한 화면에서 관리한다. `InvoiceRecord`가 단일 진실 소스이며 **1행 = 1 InvoiceRecord** 구조로 재작성되었다. 매출은 `(approvalId, productId)` 단위(제품 단위 고정), 매입은 `(approvalId, vendorCompany)` 단위로 자동 식별된다. 2026-04-22 PR #14로 MA 섹션(`maGroups` — MAContract 단위 그룹핑 + MABilling 하위에 파생 InvoiceRecord)이 추가되어 영업/MA 양쪽 계산서를 한 화면에서 조회할 수 있다.

**진행률** ███████████████████░ 95%

## 사용자 플로우

1. 월별 필터로 조회 기간 설정 (`approvalDate` 기준) + 품의코드/매출처/매입처/타입/상태 필터
2. "취소 숨기기" 토글로 CANCELLED 행 제거 가능
3. 상단 4개 요약 카드: 매출 합계 / 매입 합계 / 상태별 건수 (영업 + MA 통합)
4. 화면 구성:
   - **영업 섹션 (`groups`)** — 품의코드 rowSpan 그룹화, 각 행이 `source=SALES_APPROVAL` InvoiceRecord
   - **MA 섹션 (`maGroups`)** — MAContract 단위 그룹화, 하위에 MABilling 월별 행 + 파생 InvoiceRecord (`source=MA_BILLING`) 표시
5. 테이블에서 각 행(InvoiceRecord)의 액션 버튼으로 상태 전이:
   - **발행** (PENDING → ISSUED): 발행일·계산서번호·기타사항 입력
     - MA 섹션에서는 MABilling 행에서 발행 클릭 → `maBillingId` 전달 시 InvoiceRecord **파생 생성 + ISSUED**
   - **수정발행** (ISSUED/NEEDS_AMENDMENT → CANCELLED + 신규 PENDING): 수정세금계산서 신규 체인 생성 (`source`/`maBillingId` 복제)
   - **취소** (CANCELLED 외 → CANCELLED): 취소 사유 기록
6. 메타(발행일/계산서번호/기타사항)는 인라인으로 즉시 편집 (`InlineDateEdit` / `InlineTextEdit`) — CANCELLED 행은 편집 비활성화

## 완료 (재작성 후)

- ✅ 1행 = 1 InvoiceRecord 구조로 UI 전면 재작성 (`page.tsx`가 `"use client"` 자체 담당)
- ✅ `ActionModal` 컴포넌트 — 발행/수정발행/취소 3종 액션 동적 폼
- ✅ `InlineDateEdit` / `InlineTextEdit` — 메타 인라인 편집 (CANCELLED 시 비활성화)
- ✅ 필터: 월 / 품의코드 / 매출처 / 매입처 / 타입(SALES/PURCHASE) / 상태 / 취소 숨기기
- ✅ 4종 요약 카드: 매출 합계, 매입 합계, 상태별 건수 (영업+MA 통합)
- ✅ 품의코드 rowSpan 그룹화
- ✅ **MA 섹션 (`maGroups`)** — MAContract 단위 그룹, MABilling 월별 행 + 파생 InvoiceRecord (2026-04-22 PR #14)
- ✅ APPROVED + isLatest 품의서만 노출 (revise된 이전 버전 자동 제외)
- ✅ 신 API 3종 연동: `issue` / `amend` / `cancel`
- ✅ `issue` API가 두 소스 지원: `{ id }` (SALES_APPROVAL) / `{ maBillingId, invoiceType }` (MA_BILLING, 파생 생성)
- ✅ 체인 조회 API 연동: `GET /api/management/invoices?approvalId=...`
- ✅ PATCH endpoint는 메타(invoiceDate/invoiceNumber/remarks)만 담당 — 상태 전이는 전용 action API 사용
- ✅ `NOT_REQUIRED` 제거 — 발행 대상이 아니면 InvoiceRecord 자체가 만들어지지 않음
- ✅ 재설계 이전 구 컴포넌트 3종 deprecated stub 처리 (`InvoiceStatusPageClient`, `InvoiceFilterBar`, `InvoiceStatusTable`)
- ✅ `month` 파라미터 검증 — YYYY-MM 정규식 + 월 1~12 범위 검증, 위반 시 400 반환

## 남은 것

- ⏳ `amendedFromId` 체인 타임라인 시각화 (현재는 행 단위 나열, 수정 이력 전용 뷰 없음)
- ⏳ 엑셀 다운로드 (월별 계산서 현황 내보내기)
- ⏳ 레거시 `sales-invoice-status` / `purchase-invoice-status` API 제거 (현재 사용처 없지만 파일만 존재)
