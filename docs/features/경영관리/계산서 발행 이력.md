# 계산서 발행 이력 🟢

계산서 발행/수정/취소 이력을 `InvoiceRecord` 체인으로 관리한다. B안 결정에 따라 계산서 상태의 **단일 진실 소스**로 자리 잡았다. 발행/수정발행/취소 API 3종, `amendedFromId` 체인 헬퍼, 품의서별 체인 조회 API가 모두 구현되어 발행 현황 페이지가 이 위에서 동작한다.

**진행률** █████████████████░░░ 85%

## 식별 규칙 (체인 루트 기준)

- **매출**: `(approvalId, productId)` — **제품 단위 고정** (2026-04-22 PR #4에서 ITEM 단위 폐기)
- **매입**: `(approvalId, vendorCompany)` — 매입처가 자연 키 (제품 경계 교차)

`BUSINESS_RULES.md` §3, §4 참조.

## 완료

- ✅ `InvoiceRecord` 스키마 (`productId`, `vendorCompany` 식별 필드 + 스냅샷 + 체인)
- ✅ `amendedFromId` self-relation 체인 (`amendedFrom` / `amendments`)
- ✅ 상태 enum: `PENDING / ISSUED / NEEDS_AMENDMENT / CANCELLED` (`NOT_REQUIRED` 제거 — 발행 대상이 아니면 레코드 미생성)
- ✅ 품의서 CEO 서명 시 초기 SALES/PURCHASE 레코드 자동 생성 (`sign/route.ts`)
- ✅ 발행 API `POST /api/management/invoices/issue` — PENDING → ISSUED, 발행일·계산서번호·기타사항 기록
- ✅ 수정발행 API `POST /api/management/invoices/amend` — 원본 `CANCELLED(reason=AMENDED)` + 신규 `PENDING` 레코드 생성 (`amendedFromId` 연결, 스냅샷 덮어쓰기 지원)
- ✅ 취소 API `POST /api/management/invoices/cancel` — `CANCELLED` + `cancelledAt` + `cancelReason` 기록
- ✅ 체인 조회 API `GET /api/management/invoices?approvalId=&invoiceType=&includeCancelled=` — `amendedFrom`/`amendments` 관계 포함
- ✅ 체인 헬퍼 `lib/invoices/chain.ts`:
  - `getChainRoot(id)` — `amendedFromId=null`까지 거슬러 오름
  - `getChainAll(id)` — 루트부터 BFS로 전체 수집
  - `getChainHead(id)` — CANCELLED 제외한 유효 최신
- ✅ revise 연동: 품의서 revise 시 ISSUED 상태 InvoiceRecord를 `NEEDS_AMENDMENT`로 자동 전이
- ✅ 레거시 Product/Item invoice 필드 제거 (스키마 레벨에서 완료)

## 남은 것

- ⏳ 전용 이력 시각화 UI (품의서별 체인 타임라인 페이지) — 현재는 발행 현황 테이블 내에서만 조회 가능
- ⏳ `NEEDS_AMENDMENT` 상태의 자동 알림 (revise가 ISSUED 계산서에 영향 줬다는 경고)
- ⏳ 체인 무결성 검증 스크립트 (orphan `amendedFromId`, 순환 참조 방지)

## API 엔드포인트

- `POST /api/management/invoices/issue` — 계산서 발행 (PENDING → ISSUED)
- `POST /api/management/invoices/amend` — 수정발행 (체인 생성)
- `POST /api/management/invoices/cancel` — 발행 취소
- `GET /api/management/invoices?approvalId=...` — 품의서별 체인 조회 (체인 관계 포함)
