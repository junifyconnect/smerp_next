# 계산서 발행 이력 🟢

계산서 발행/수정/취소 이력을 `InvoiceRecord` 체인으로 관리한다. B안 결정(결정대기 #1)으로 계산서 상태의 **단일 진실 소스**로 자리 잡았고, 2026-04-22 PR #13에서 **`source` enum (SALES_APPROVAL | MA_BILLING) + `maBillingId`** 도입으로 영업/MA 양쪽 계산서를 같은 체인 모델로 다루게 되었다. 발행/수정발행/취소 API 3종, `amendedFromId` 체인 헬퍼, 품의서별 체인 조회 API가 모두 구현되어 발행 현황 페이지가 이 위에서 동작한다.

**진행률** ███████████████████░ 95%

## 식별 규칙 (체인 루트 기준)

- **매출 (SALES_APPROVAL)**: `(approvalId, productId)` — **제품 단위 고정** (2026-04-22 PR #4에서 ITEM 단위 폐기)
- **매입 (SALES_APPROVAL)**: `(approvalId, vendorCompany)` — 매입처가 자연 키 (제품 경계 교차)
- **MA (MA_BILLING)**: `(maBillingId, invoiceType)` — MABilling(월별 청구 행) 당 매출 1건 + 매입 1건 최대. `approvalId`는 null, `maBillingId`로 역참조.

`BUSINESS_RULES.md` §3, §4, §10 참조.

## 완료

- ✅ `InvoiceRecord` 스키마 (`productId`, `vendorCompany`, `source`, `maBillingId` 식별 필드 + 스냅샷 + 체인)
- ✅ `source` enum: `SALES_APPROVAL` | `MA_BILLING` (2026-04-22 PR #13)
- ✅ `maBillingId` 선택 FK — MA 파생 레코드 역참조용
- ✅ `amendedFromId` self-relation 체인 (`amendedFrom` / `amendments`)
- ✅ 상태 enum: `PENDING / ISSUED / NEEDS_AMENDMENT / CANCELLED` (`NOT_REQUIRED` 제거)
- ✅ 품의서 CEO 서명 시 초기 SALES/PURCHASE 레코드 자동 생성 (`sales-approvals/[id]/sign/route.ts`, source=SALES_APPROVAL)
- ✅ **MA CEO 서명 시**: InvoiceRecord는 **생성하지 않음**. MAContract/MABilling만 만들고, 월별 발행 시점에 issue API가 파생 생성 (B-2 설계)
- ✅ 발행 API `POST /api/management/invoices/issue` — 두 모드 지원:
  - `{ id }` — 기존 InvoiceRecord(SALES_APPROVAL) PENDING → ISSUED
  - `{ maBillingId, invoiceType }` — MABilling 기반 InvoiceRecord(**파생 생성** + ISSUED 세팅, `source=MA_BILLING`)
- ✅ 수정발행 API `POST /api/management/invoices/amend` — 원본 `CANCELLED(AMENDED)` + 신규 `PENDING` 체인 생성. **원본의 `source`/`maBillingId` 복제**하여 MA 체인도 유지 (PR #13)
- ✅ 취소 API `POST /api/management/invoices/cancel` — `CANCELLED` + `cancelledAt` + `cancelReason` 기록
- ✅ 체인 조회 API `GET /api/management/invoices?approvalId=&invoiceType=&includeCancelled=` — `amendedFrom`/`amendments` 관계 포함
- ✅ 체인 헬퍼 `lib/invoices/chain.ts`: `getChainRoot` / `getChainAll` / `getChainHead`
- ✅ revise 연동:
  - 영업 품의서 revise → SALES_APPROVAL InvoiceRecord 중 ISSUED → `NEEDS_AMENDMENT`, PENDING → `CANCELLED(REVISED_v{n})`
  - MA 품의서 revise → MA_BILLING 파생 InvoiceRecord 중 ISSUED → `NEEDS_AMENDMENT`, PENDING → `CANCELLED(REVISED_v{n})`
- ✅ 레거시 Product/Item invoice 필드 제거 (스키마 레벨에서 완료)

## 남은 것

- ⏳ 전용 이력 시각화 UI (품의서/계약별 체인 타임라인 페이지)
- ⏳ `NEEDS_AMENDMENT` 상태의 자동 알림 (revise가 ISSUED 계산서에 영향 줬다는 경고)
- ⏳ 체인 무결성 검증 스크립트 (orphan `amendedFromId`, 순환 참조, source/maBillingId 정합성)

## API 엔드포인트

- `POST /api/management/invoices/issue` — 발행 (PENDING → ISSUED) / MA_BILLING 파생 생성
- `POST /api/management/invoices/amend` — 수정발행 (체인 생성, source/maBillingId 복제)
- `POST /api/management/invoices/cancel` — 발행 취소
- `GET /api/management/invoices?approvalId=...` — 품의서별 체인 조회
